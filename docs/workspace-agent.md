# 工作区助手

工作区助手使用现有的内置 Pi Rust Agent 核心整理任务和规划需求，模型调用在 Bridge 进程内完成。用户明确要求执行工作时，Bridge 会校验规划结果，并在对应项目中创建普通编程会话。任务目录、范围筛选、持久化、调度和设置修改由 Bridge 实现。

## 使用

- 默认只从用户明确提出或确认的开发交付目标中识别任务，例如功能实现、修复、重构、测试、部署和项目配置；普通问答、代码解释、闲聊及无开发交付目标的讨论不计入。已有任务的澄清和进度询问归入原任务。
- 在“设置 → 助手 → 任务分析提示词”中可编辑识别规则、恢复默认并保存。提示词保存在当前 Bridge，所有客户端和主会话共用，重启后保留；清空保存也会恢复默认。关闭自动分析时仍可编辑规则，保存不会开启或触发自动分析。
- 首页通过统一的“任务”列表展示分析结果，默认查看未结束任务；可以筛选状态和项目，展开任务后进入来源会话。
- 会话详情右侧显示该会话已识别的任务，包括待验收、已完成、进行中、待继续、待解决和已取消任务。窄屏通过会话菜单中的“会话任务与助手”访问。
- “问问工作区助手”打开独立对话入口。可查询任务及项目信息、主动要求重新分析任务、调整分析范围，或修改所选项目的审批说明。设置修改会显示具体预览，点击“应用修改”后写入现有设置接口。
- 助手按优先级使用已启用且指定模型的模型供应商，支持 OpenAI Chat Completions、Responses 和 Anthropic Messages。依次尝试已配置的供应商，并将已有 AI 审批模型作为备用。一次请求最多尝试 3 个配置，共用 75 秒总超时；认证失败会明确提示更新密钥。无需开启 AI 自动审批，也无需安装或启动编程 Agent。

助手要求模型返回完整 JSON。回复为空、JSON 无效或达到输出 token 上限时，会在原服务与模型上自动重试一次，保留原请求及附件上下文，并共用原来的 75 秒总超时；达到输出上限时，重试额度从 6,000 提高到 12,000 tokens。仍然失败时会区分空回复、无效 JSON、输出截断与模型拒绝。未完整返回的内容不会用于修改设置、更新任务状态或创建执行会话。Bridge 日志只记录停止原因、文本字节数和 JSON 错误位置，不记录模型回复、用户输入或密钥。

## 聊天输入与模型选择

首页的主 Agent 使用随内容调整高度的紧凑对话入口，保留模型选择、附件、新会话、历史会话入口，以及最近两条调度任务的状态、进展和操作菜单，不展示完整聊天正文。发送消息后立即导航到会话详情页，继续等待回复和对话；也可直接打开当前主会话。首页输入框和详情页共用草稿、模型及执行 Agent 配置，支持仅发送附件；返回首页不丢失未发送或发送失败的草稿，重新进入后重试复用请求编号及已成功上传的文件。主 Agent 入口位于首页上方，最近会话与任务列表在下方宽屏并排、窄屏纵向排列，三块的显示设置继续独立保存。

会话页与首页、会话详情页共用完整的下拉菜单组件，沿用会话页的摘要文字、下拉箭头和选中标记。模型选择包含模型服务与模型两项；选择服务后直接列出该服务的模型，选择模型或提交自定义模型名后立即保存。服务尚未选定模型时关闭菜单，不改变此前选择。模型选择器可切换已启用的模型服务，从服务的模型列表选择，或手动输入模型名。主 Agent 的模型选择和执行 Agent 按主会话保存在 Bridge 的助手记忆文件中，进入历史会话时恢复原选择。每次启动应用创建新的主会话，包括同一电脑使用相同客户端身份多开；不会自动带入上一轮聊天。各主会话可分别选择模型，在同一会话内切换项目范围仍使用该会话的配置。任务识别仍使用 Bridge 的共享分析配置与缓存。保存失败保留此前选择。手动指定模型时只调用指定服务和模型；服务不可用会提示重新选择。选择“自动选择”恢复原有按优先级及备用模型的路由。主 Agent 模型切换只影响当前主会话后续的对话和新任务，不改变其他主会话或共享任务分析的模型。旧协议的共享分析模型行为保留。

附件复用现有上传接口。Bridge 按上传 ID 从自身上传目录读取实际内容，不请求客户端提供的 URL 或路径。图片支持 PNG、JPEG、WebP 和 GIF，以图片内容块送入模型；UTF-8 文本、代码和 Markdown 等文件作为文本内容送入模型。单条最多 8 个文件，合计最多 10 MB，单个文本最多使用 50,000 字符并标记截断。其他二进制格式会明确报错。新协议完整持久化聊天及附件元信息；模型读取最近 60 条聊天，每条文本最多 4,000 字符，较早的完整消息仍可在历史会话中浏览。旧协议保留最近 40 条聊天、读取最近 12 条的兼容行为。后续提问会在本次模型上下文范围内重新读取附件，并与本条附件共享数量和大小上限，优先保留本条附件。

## 输入命令与引用

首页和助手详情页的输入框支持 `/` 补全助手命令：`/new` 新会话、`/history` 历史会话、`/memory` 长期记忆、`/model` 模型选择、`/help` 使用说明。这些命令直接操作相应界面，不发送给聊天模型。支持点击、方向键、Enter/Tab 选择，Esc 关闭；补全浮层不改变输入区高度。

`@` 补全项目文件，未指定项目时先选择引用项目；目录可继续逐层浏览，含空格的文件名自动加引号。引用作为草稿的一部分保留，首页进入详情页及切换历史会话时不丢失。客户端随消息提交 `references:[{kind:"file",project_id,path}]`，Bridge 在项目目录内读取真实文件内容供助手参考；单次最多 16 项引用，单个文件最多 16 KB，文件合计最多 64 KB，并标记截断。项目范围、相对路径及符号链接边界均会校验。

执行 Agent 为 Codex 时，`$` 列出所选项目可用的技能。`GET /agents/commands` 新增 `project_id`，无需预先创建执行会话；原 `session_id` 用法保持兼容。选中的技能通过 `{kind:"skill",project_id,name}` 传递，并在该项目的新执行指令开头保留 `$技能名`。文件内容作为参考数据处理；选中引用本身不会创建任务或授权执行。

## 主会话与长期记忆

助手详情页展示当前项目概览。手选项目优先；未限定项目时，助手根据本轮对话返回经过真实项目目录校验的 active_project_id，并按主会话保存。执行计划或显式文件/技能引用只涉及一个项目时也可恢复该上下文；旧历史会话只从自身最近的执行请求恢复，不借用其他会话的项目。新会话不自动继承旧项目。宽屏在右侧展示，窄屏通过顶部项目摘要或“项目概览”打开，继续随会话轮询更新。

项目概览包含目录、Git 分支、工作区是否有改动、暂存/未暂存/未跟踪文件数量、相对已知上游的领先/落后数量及最近提交。Git 查询只读，有 2 秒超时，结果在同一 Bridge 内共享 3 秒缓存；不执行 fetch、提交或修改工作区。Git 不可用时显示未知状态。相同 Git 事实也传给助手，用于回答当前项目问题；提交说明仍是不可信数据，干净状态或新提交不代表任务完成或验收通过。

相关任务按当前项目筛选，默认显示未结束任务，可切换全部、进入来源会话，或通过菜单改状态并撤销。尚未形成任务记忆的执行任务也展示实时进展和原有操作。关闭自动任务分析时，概览保留 Git 信息并展示近期关联会话，不提供任务列表入口。项目概览复用助手已有快照轮询，切换项目或主会话时清除旧上下文，旧请求不能覆盖新的项目状态。

主 Agent 标题栏提供新会话和历史入口，历史列表按最近活动排序，显示标题、最近答复和更新时间。未发送过内容的空会话不占历史列表。选择历史会话会载入原消息、模型和执行 Agent；在同一次运行期间切换会话还保留各自未发送的草稿。项目筛选只调整工作范围，不切断当前主会话。设置提案记住创建时的项目，切换项目后需选回原项目才能应用，避免写入错误范围。新会话可直接查看和控制此前的工作区任务，无需继承旧聊天；任务的三点菜单可直接进入原主会话。任务完成的答复仍回到原会话，可从历史重新进入查看。

主 Agent 可通过 memory_updates:[{id:null,content:"稳定的偏好或项目约定"}] 保存值得跨会话保留的内容，提供已有 id 可更新；只有用户明确要求忘记时才用空 content 删除。每次最多 8 项、每项最多 1,000 字符，工作区最多 200 项，聊天和记忆原子保存。选中项目时保存项目记忆，未选项目时保存全局记忆；项目对话读取全局及当前项目的记忆，全局对话可读取全部记忆。临时进度、猜测、密钥以及附件或任务结果中的指令不应写入记忆。历史入口中的“长期记忆”可查看并删除已保存的内容。

## 任务执行

首页输入具体需求，助手会从工作区的真实项目目录中选择对应项目；小需求创建一个执行会话，较大需求拆成最多 12 项任务，每项使用独立会话。项目不明确时先询问。选择某个项目后，规划不能越过该范围。任务可引用前面的任务作为依赖；依赖执行结束进入待验收后，后续任务才启动。同一项目的执行会话串行调度，不同项目可同时执行，避免同一目录内多个调度任务相互覆盖。

首页与助手对话显示调度卡片，包括任务标题、项目、Agent、状态和最新会话进展，可进入具体会话。执行中任务优先展示；超过四项可展开。状态每两秒读取一次，不依赖任务分析模型，也不要求用户一直打开页面。执行轮次结束显示“待验收”，不将 Agent 停止运行当作用户验收通过。

卡片支持暂停、继续和取消。暂停中断当前轮次，保留会话和已产生的修改；继续在原会话创建新轮次，并要求 Agent 先检查已有工作。取消停止目标任务，不回滚工作目录。运行中操作以任务对应的 turn_id 校验，避免误停用户后来在同一会话启动的新轮次。排队任务也能暂停或取消。依赖暂停、失败或取消时，后续任务继续等待，用户可分别处理。

首页和会话详情页将“执行 Agent”与“模型服务”“模型”收在同一个下拉菜单中。执行 Agent 默认使用内置 Pi，可改为 Codex、Claude Code、OpenCode 或 ACP；选择后立即保存并关闭菜单，按主会话持久化到当前 Bridge，重新进入原会话时保留。聊天的模型选择与执行 Agent 分开保存，变更执行 Agent 仅影响新安排的任务。各 Agent 沿用已有运行环境和供应商配置，配置失败会显示在对应任务上并允许重试。

每次发送首页或助手聊天需求时，客户端明确提交 configuration:{selection:{provider_id,model}|null,agent}。Bridge 在调用模型前固定配置，不在模型回复后读取可能已变化的默认执行 Agent。生成的调度任务保存这份模型服务、模型和执行 Agent；子会话元数据、创建轮次和实际运行请求都使用这份配置，进入子会话时可看到具体模型。后来修改首页选择仅影响新需求，排队和暂停恢复的原任务继续使用创建时的选择。手选服务不可用或不兼容所选执行 Agent 时明确显示任务失败，不静默切换到其他模型。

子任务执行结束、失败或取消后，结果会自动交回对应的主任务。主任务使用创建时的模型，根据原需求与各子任务的完整结果生成答复，分步返回阶段结果，所有子任务返回后给出综合答复，不把待验收当作用户已验收。主任务答复保存在发起需求的原始主会话中，即使用户已新建或切换到其他会话也不会混入新对话；完整答复在会话详情页中显示，首页保持输入入口与简要任务进度。打开的助手对话每两秒读取新答复，不清空输入草稿，不强制打断用户向上阅读。

结果回传在独立后台工作中进行，最多同时两项，不持有聊天或调度控制锁，生成答复时仍可追加需求、询问进度、暂停其他任务。任务与主需求 ID、原需求、模型选择、结果通知版本均持久化，重复轮询或重启不重复发布已返回的答复；模型或存储失败保留待回传结果，按 2–60 秒退避重试。回传失败时保留待生成状态，稍后自动重试。单项最多使用约 24,000 字符、全部子结果合计约 100,000 字符；较长结果保留开头和结尾并标记截断，传入的是会话正文结果而非卡片的简短摘要。

调度后台与助手聊天互相独立。询问进度不会创建新的执行任务，新增需求不会取消旧任务。聊天请求携带 UUID request_id，失败重试复用同一个编号；Bridge 原子保存聊天、调度记录和最近 100 个请求的回执，避免响应丢失后重复调度。相同编号的内容变化返回冲突。旧客户端不携带编号时仍兼容，但不能保证重复提交去重。

Bridge 重启后重新检查已保存的执行轮次，未完成轮次按现有会话恢复规则标记为中断，用户可以继续；已排队任务在后台调度器启动后继续检查依赖。不会仅凭旧的运行状态重放已有轮次。

首页主 Agent、最近会话和任务列表分别使用与各自布局匹配的骨架屏，初次加载并发进行，哪个区域先就绪就先显示。主 Agent 只等待自己的模型与执行 Agent 配置；任务区读取自身任务快照；最近会话不再等待项目目录或 Codex Profile 元数据。项目、会话和 Profile 请求分别更新结果，目录元数据失败不遮挡其他可用区域，空列表也会及时显示空状态。已显示区域刷新时保留内容和草稿，不重新切回整块骨架屏；过期请求不会覆盖新一轮刷新结果。

## 范围与开销

每次分析记录有效提示词的指纹。提示词修改或旧缓存没有指纹时，下次分析会重新核对该范围的近期正文及已有任务；原任务保留 ID、来源和人工状态，仅明确不符合新规则的任务可移出识别结果。模型必须逐项列出移除的原任务 ID，未知 ID、冲突或没有说明的遗漏会被拒绝。正文截断时不能确定旧任务是否符合新规则则保留。分析失败保留旧结果和指纹，后续重试；分析过程中修改提示词会丢弃旧规则的返回结果，避免覆盖新配置。同一提示词重复保存不会额外调用模型。

所选项目中，通过 Bridge 参与过的会话默认全部纳入，不受时间和数量限制；未通过 Bridge 交流的外部或导入会话默认不识别任务。用户手动开启后，外部会话单独限制为最近 5 天、最多 15 个，不占用 Bridge 会话名额。外部会话按最近活动排序后选取，最终列表仍按活动时间排序。项目筛选首先生效，自动验收内部会话始终排除。参与记录来自 Bridge 的本地会话和运行状态，单纯读取归档不会被当作参与。接口分别返回 participated_sessions 和 external_sessions，页面展示两类数量。

外部会话范围可设置为 1–365 天、1–100 个会话；“也分析未参与过的会话”默认关闭，手动开启后持久化保存。已有明确保存的范围设置继续生效，项目未单独设置时继承全局范围。后台先筛选目录，再读取所选会话正文；不会将完整会话目录发送给模型。前端进入页面时触发分析，运行时每 2 秒查询结果，空闲时每 60 秒检查更新。同一后端中的请求排队执行并按范围合并。短暂断连保留已有任务，并按 1、2、4、8、16、30 秒间隔自动重试，之后间隔保持 30 秒；连续失败三次才显示连接异常提示，不展示原始管道错误。认证及业务错误不作为断连重试。切换项目或连接会取消原范围的重试。

自动分析必须同时确认会话活动时间、正文来源版本均未变化，且存在内容指纹，才能跳过正文读取。Codex 和 Pi 使用正文文件的大小及纳秒修改时间作为轻量版本；关联的提供商会话也计入版本。无法提供可靠来源版本时读取正文核验，不依赖目录时间直接跳过。Codex 目录活动时间取索引时间与正文修改时间的较新值，正文追加使目录缓存失效。旧缓存首次遇到会重新核验。读取后比较消息 ID、角色和完整正文的 SHA-256 指纹，不计入消息时间等元数据。内容相同只更新活动时间缓存，不调用模型，也不改变上次成功分析时间。仅追加消息且旧消息前缀的指纹一致时，模型只接收新增消息及此前任务记忆；历史内容修改、删除、重排，或旧缓存没有指纹时，回退到近期正文重新分析。读取正文仍经过现有消息接口，增量优化主要减少模型输入。

点击“更新任务”，或在助手聊天中明确要求分析、重新分析、刷新任务，会强制分析当前范围，绕过活动时间和内容指纹缓存，重新读取近期正文。普通任务查询和自动轮询不会强制分析。正在运行时的手动请求会排队；同范围待执行请求合并时保留强制标记，后续自动请求不能覆盖它。聊天只确认请求已入队，完成后任务列表更新。前端每个分析请求携带 UUID request_id，连接重试复用同一编号；同一 Bridge 进程保留最近 256 个已接受请求编号，重复请求不重复强制分析。已接受分析后的状态读取失败，只重试读取。重启后去重编号会清空。

每次模型输入最多使用最近 300 条消息、100,000 字符，单条上限 12,000 字符，并携带此前已识别的任务；增量分析对新增消息应用相同限制。截断会在任务卡片标注“基于近期内容”，增量更新保留此前的截断标记。超长且首次分析的历史不保证覆盖所有较早任务；已识别任务在后续分析中必须保留。会话侧栏仍可查看当前范围外的已有任务记忆；强制分析也遵守配置的范围限制。

## 任务进度展示

首页统一展示“任务”列表，沿用原工作进度的列表样式，不再单独展示最近跟踪摘要与展开后的重复列表。状态筛选提供未结束、全部状态及六种具体状态，默认未结束；已完成、已取消及旧归档记录可以通过对应状态或全部状态查看。具体状态先筛选匹配子任务，再进行分组；默认未结束视图保留进行中分组的完整子任务，便于继续验收与撤销。筛选仅切换当前列表，不触发重新分析，也不影响主 Agent 草稿或关联的执行任务。识别来源设置直接位于任务标题右侧的“分析范围”按钮中。

任务摘要只显示一句简短的当前进展，不展开；以当前结果、阻塞点或下一步为主，避免复述请求和操作经过。目标为 20–35 个中文字符，必要时最多 50 字；英文最多 120 字符。不生成阶段图、百分比或虚构流程。HTTP 404 等错误码保留，但不能仅凭错误码推断具体原因。点击任务进入来源会话。超过默认展示数量时，列表底部显示文字居中、整行可点击的展开与收起按钮。

任务按最近更新时间倒序排列，时间相同保持原顺序，缺少时间的记录排在末尾；首页、归档列表和会话任务使用同一排序。任务下方显示项目、任务持续时间和最近更新时间，时间文字直接显示“5分钟前”等，不再附加“更新”，也不显示近期内容截断图标。时间由 Bridge 根据任务最初的来源消息及状态依据消息计算，同一会话中的多个任务分别计时；任务 ID 不变时保留原起点，已完成或取消后停止计时，再次打开则继续按原起点计算。持续时间包含等待时间，不代表实际执行工时。缺少依据时不显示持续时间，不使用会话起止时间补足。旧 Bridge 没有任务更新时间时使用会话时间排序，时间文字保留“会话”前缀以区分来源。公共格式化函数 lib/src/utils/time_format.dart 将 7 天内的更新显示为刚刚、几分钟前、几小时前或几天前，较早时间显示本地年月日；前端每分钟刷新时间文字。

任务操作菜单提供全部六种状态：待继续、进行中、待验收、待解决、已完成、已取消。用户可从任意状态手动切换到任意状态，单项、整组及按状态筛选后的批量处理使用同一接口；人工决定不受模型自动判定的状态转换约束。已完成或取消的任务从默认未结束列表移出，通过状态筛选仍可查看和修改。独立归档入口已移除，旧归档记录仍保留并可在全部状态或对应状态列表中恢复，不会被悄悄改成取消。成功操作提供撤销入口。

点击“会话任务”可在当前列表展开同一会话的关联任务，包括已结束任务。按待验收、进行中、待解决、待继续、已完成和已取消筛选；“一键验收”只处理当前待验收列表，“一键完成”只处理当前待解决列表，“一键取消”只处理当前所选的未结束状态。请求携带统一 expected_status，任何目标状态已变化时整批返回 409，不会部分执行。操作使用 UUID request_id 幂等，保留最近 100 次操作的撤销记录；撤销也幂等，已有更新的人工决定时返回 409。人工状态按会话和任务 ID 持久化，后续模型分析不覆盖，任务起点保留、结束时间以人工决定时间为准，撤销恢复之前状态及时间。

Agent 可将重复请求或同一交付目标的多个部分合并展示。原任务 ID、标题、来源、状态和证据全部保留，各子任务仍可独立验收、取消、重新打开。合并使用稳定 group 元数据，同项目跨会话合并通过经过校验的 groups 提案引用准确的会话及任务 ID，只能引用当前分析范围提供的同项目任务。分组不意味着验收，不改变子任务状态；同组存在待解决或进行中任务时，父级也不会显示已完成。跨会话分组与本次分析使用同一次原子保存。

历史缓存分别携带展示版本和任务状态规则版本。展示版本 0 的旧长摘要会重新核验；版本 1 在正文未变时仅补充任务时间，不再调用模型。任务状态规则版本 0 在下次后台整理时重新判定一次，补充待验收分类与合并关系，成功后不再重复分析；失败保留旧任务和版本。旧结构化 progress 字段兼容读取，但客户端不再渲染。

## 状态和持久化

任务记录保留来源消息、状态依据消息、独立状态及摘要。会话空闲、一轮结束、用户开始下一项任务、切换会话及沉默均不作为任务验收依据。实现已交付、等待手工验证或重启后确认生效时使用 awaiting_review；只有具体错误、权限缺失或依赖不可用才使用 blocked。完成条件跟随用户原始交付目标：只要求代码实现且有通过测试的证据时可以完成，要求线上生效则等待相应证据。模型返回的数据必须通过结构及消息引用校验；错误保留已有任务并显示更新失败，不能将分析失败显示成全部完成。

存储文件位于会话元数据文件旁，扩展名为 `workspace-agent.json`，使用原子替换保存任务、消息数量与内容指纹、范围、兼容的旧归档状态、人工任务状态、批量操作记录及最近 40 条助手聊天记录。旧存储格式兼容读取；分析失败不推进指纹或消息游标，重试仍包含未成功分析的消息。来源版本在读取正文前记录，分析期间新追加的消息会触发下一轮核验，避免把尚未看到的完成消息误当成已处理。助手每次使用最多最近 12 条聊天、120 个任务摘要，避免大范围查询产生无界上下文。未识别的会话标题可由最新任务标题补足；用户标题覆盖优先。

用于整理和规划的 Pi 工具注册表为空，不加载普通编程会话的 Bash、文件工具、项目规则或插件。调度产生的执行会话沿用所选 Agent 的正常工具、项目规则、插件与审批流程。项目设置写入仅通过受类型校验的后台接口执行，所有助手 API 沿用 Bridge 客户端认证，模型密钥不进入对话上下文。

## 聊天修改任务状态

用户可直接输入“所有任务都标记完成”“把导出任务改为进行中”“将待验收任务改为待解决”等指令。聊天可把任意原状态改为六种状态中的任意目标状态，和前端菜单使用同一套持久化人工决定、并发校验及撤销记录。具体任务存在歧义时助手先澄清；当前项目筛选限定修改范围。“所有任务”包含范围内历史及旧归档任务，已处于目标状态的任务不重复更新时间；“所有未完成任务”仅匹配四种未结束状态。

模型返回结构化 task_action，不能通过生成文字直接改状态。Bridge 从本次请求保存的完整任务快照解析 all 或具体 session_id/task_id，超出模型 120 项上下文的任务也会处理，不会只改模型看见的前 120 项。逐项校验预期状态，任何目标已变化时整批拒绝。聊天、人工状态、撤销记录和请求去重回执原子保存；返回消息带真实处理数量及撤销按钮。撤销状态保存在聊天记录中，刷新或重开窗口后仍可识别。状态标记不代表执行会话真的完成，也不停止或回滚执行会话；运行控制仍由调度卡片的暂停、继续和取消处理。

## API

所有路径均接受可选的 `project_id` 查询参数。未传时使用全局项目范围。更新后的客户端发送 `X-Omni-Code-Workspace-Scope: conversation` 及 `X-Omni-Code-Conversation-Id: <UUID>`，按主会话保存对话和模型配置。客户端 ID 与 token 继续用于 Bridge 认证，不作为新协议的对话隔离边界。会话 ID 在应用进程内保存，普通页面导航、连接重试不会新建会话；应用启动、切换 Bridge 或点击“新会话”生成新 ID，选择历史会话则切回持久化的 ID。不同主会话可并发聊天；同一项目的执行任务仍按目录串行调度。工作区任务、任务控制、进度和长期记忆跨主会话共享。旧共享协议及 `client` 范围协议仍兼容；首次使用新协议时，原有共享及客户端对话转为可选择的历史会话，任务和进行中的结果回传关联到迁移后的原会话。两端需一起更新。

## 验证

会话回归覆盖同一认证身份下不同主会话的模型、执行 Agent 和上下文隔离，共享任务进度与控制、长期记忆跨会话读取与删除、完整历史保存与重启恢复、旧会话迁移和进行中的结果返回原会话。并发测试同时验证旧客户端范围和新主会话范围的配置固定、并发发送和返回归属。前端覆盖紧凑首页入口、发送后进入详情且只提交一次、历史选择进入详情、跨页面失败重试及附件复用、所有显示设置组合，以及启动时生成独立会话 ID、新建会话与历史切换、旧响应隔离、草稿和模型配置恢复、记忆查看与删除，以及配置读取失败时保留草稿并阻止误用默认配置。

后端测试覆盖范围边界、来源证据、多个任务独立状态、历史截断、存储恢复和旧格式兼容、标题补足、Pi 模型调用、缓存不读取正文、元数据变更不调用模型、新增消息增量输入、目录时间未变及分析期间追加完成消息、历史编辑回退、失败重试、强制分析 HTTP 参数及请求去重、聊天触发和强制请求合并，任务独立时间、终态时长固定、元数据升级不调用模型、旧状态规则一次性升级、归档兼容、任务分组证据与跨会话引用、批量处理鉴权与幂等、混合状态整批拒绝、持久化和撤销冲突，以及设置修改。客户端测试覆盖自动轮询与手动强制分析的区分、运行中手动入队、断连退避重试、状态读取失败不重复提交、切换项目取消旧重试、认证失败不重试、任务导航、范围表单校验、窄屏侧栏、聊天失败保留输入、修改预览和应用，连接切换后的旧响应隔离、验收历史与撤销、失败保留任务、关联任务按状态筛选及批量处理、合并任务保留子任务且可独立处理、简短摘要和元信息在窄屏及大字体下的布局，以及公共时间格式化边界。

合并任务右侧提供统一三点菜单，可选择六种目标状态中的任意一种；整组修改会覆盖组内所有与目标状态不同的子任务，包括已结束子任务，可一次撤销。已结束分组也可选择任意目标状态。混合状态整组请求在每个 tasks 项中携带 expected_status，优先于顶层统一值逐项校验；任意任务状态过期时整组拒绝，不会部分修改。关联任务按状态筛选的批量操作仍使用顶层统一 expected_status。

后台任务检查会读取所选项目的 Git HEAD 和最新提交标题，每个项目每轮读取一次。发现提交版本与该会话上次成功分析的版本不同，会重新核对会话任务，即使会话正文未变化；成功后持久化提交版本，失败保留旧版本供下次重试。此检测随任务面板的后台轮询或手动刷新运行，不安装 Git hook，也不在面板关闭后单独监控仓库。提交仅是复核线索，不等于验收、测试通过或部署完成；人工状态继续保留。

首页合并任务主体点击后进入关联会话中更新时间最近的一项，子任务按钮单独负责展开。窄屏首页顶部使用 Omni Code 应用 Logo。

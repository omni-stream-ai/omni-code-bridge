# x11box 验收插件部署（开发分支）

当前实现仍在验证，不能作为生产就绪声明。发布验收项目见
[x11box-acceptance-plan.md](x11box-acceptance-plan.md)。

## 安装位置与方式

这是 Bridge 管理的可选运行时插件。手机发起安装，环境部署在运行 Bridge 的 Linux 机器上。每次验收启动一个独立 Docker 容器。手机只访问 Bridge 的鉴权网关。宿主机需要预先安装 Docker，Bridge 服务账号需要能够使用本机 Docker daemon。当前网关通过本机回环地址访问容器，不支持远程 Docker daemon。

开发环境可在 Bridge 服务启动前配置：

	export OMNI_CODE_X11BOX_SOURCE=/path/to/x11box

客户端选择“安装环境”后，Bridge 使用内置 deploy/x11box.Dockerfile 与该目录源码构建镜像，随后执行健康检查。安装失败可重试；安装中重启 Bridge 会标记中断，需要重试。

固定版本应配置不可变镜像摘要：

	docker image inspect --format '{{.Id}}' omni-x11box:acceptance
	export OMNI_CODE_X11BOX_IMAGE='sha256:<完整摘要>'

不要使用浮动 tag。反向代理必须转发 WebSocket Upgrade，外部访问使用 HTTPS，不要公开容器的 Xpra 14500 或 x11box 27811 端口。

手机可从项目或会话进入验收，项目不要求使用 Git。有提交的 Git 仓库使用记录的提交快照；普通目录和尚无提交的仓库使用创建验收时冻结的目录快照，以 snapshot-sha256 摘要标识。目录快照排除版本控制数据、常见依赖缓存、本地 .env 和凭据配置，保留 .env.example 等模板及应用源码、静态产物，不跟随指向项目外的符号链接。人工控制期间自动化指令被拒绝；控制租约 90 秒。桌面票据单次使用、30 秒有效；浏览器会话最长 1 小时。录像支持 Range 下载。卸载会停止活动验收并保留产物。

启动命令留空时，由 Agent 选择应用类型和启动方案。网页方案使用 `kind: web`、服务启动命令和本地 `url`，Bridge 等待地址就绪后打开带 CDP 的 Chromium；静态网页可以省略命令。原生桌面方案使用 `kind: desktop`、应用启动命令和用于匹配窗口的 `app` 标题或类名，无需 URL，Bridge 不会添加浏览器或要求 CDP。镜像内可用工具以实时探测为准；所有环境使用真实的包管理器与 SDK，不会替换为 npm 兼容命令；首次安装依赖可能需要几分钟，网页服务就绪等待上限为 15 分钟。Agent 的命令通过容器内的 shell 在 `/workspace` 执行，支持引号、安装／构建步骤和脚本。验收原生应用时使用 X11 窗口观察、点击、输入、快捷键和截图，缺少可验证证据时不能判定通过。

业务验收范围与运行依赖分别判断：仅验收客户端焦点、导航等交互，也必须准备为页面提供真实数据的后端/API 等服务。识别上下文包含 README 和 Compose/Procfile 编排，环境准备同时收到已确认用例，用于补齐隔离服务、连接、认证和最小测试数据。旧的仅客户端环境缓存不会继续复用。

启动 JSON 可提供 `services`，每项包含 `name`、前台 `command`、可重复的只读 `ready_command` 和 `timeout_seconds`（默认 60，范围 1–180）。Bridge 按顺序后台启动服务，检查存活并等待就绪，所有服务就绪等待合计最多 180 秒；随后执行可选 `prepare_command`，成功后才启动客户端。窗口可见不能替代服务及数据准备成功，每个验收项开始前会再次检查依赖。服务退出、就绪超时或准备失败会携带名称和日志阻止继续执行；客户端退出时清理其依赖进程组。所有操作均在本轮容器内，不使用宿主服务、令牌或用户会话数据。

自动验收采用逐步视觉反馈：每次将真实截图和此前操作结果交给执行 Agent，只执行其返回的一条指令，再截图决定下一步。Codex 使用结构化 localImage 输入，Pi 使用图片内容输入；最终裁判也接收实际图片。原生点击坐标以应用截图左上角为原点，越界坐标不执行。每项最多 48 次操作、20 分钟，达到上限或缺少前置条件标记 blocked，不能由最终裁判覆写为通过；业务断言不符则记录 failed。

自动验收在执行清单前开始录像，保存初始画面和每一步操作后的截图；操作结束后立即导出 MP4 和 JSON 报告，桌面继续运行，供人工查看或接管。原生应用截图按 `app` 匹配窗口，减少空白桌面。客户端“验收证据”中的“回放操作录像”在 App 内播放，支持暂停、拖动进度和重播；截图是补充证据。移动端通过已鉴权的 Bridge HTTP 客户端下载到临时文件再播放，避免原生播放器的网络代理配置导致请求失败，退出播放器后清理缓存。旧记录尚未导出录像时，可点击“生成录像与报告”；自动验收仍在执行时不能提前结束录像。

会话入口的自动验收在创建时冻结该会话的完整用户消息。长会话按批次交给 Agent 整理，保留早期目标和后续补充，后续纠正、取消和范围缩小优先；Agent 回复只作辅助背景。每批提炼使用独立的隐藏内部会话，执行 Agent 仅接收最终需求摘要，避免历史工具日志挤占上下文。客户端可填写“本次验收重点”补充或限定范围，并查看提炼后的需求。每条需求保存来源用户消息 ID，验收清单通过 requirement_ids 关联并校验覆盖，遗漏会要求 Agent 修正；最终判定也必须覆盖全部检查项。会话后续新增消息不会自动改变已创建验收的范围；确认前可在测试用例页沟通或手动调整，确认后需要新范围时重新创建。有提交的 Git 仓库仍需先提交待验收修改；目录快照在创建后不随项目文件变化而更新。

## 二进制应用的环境准备

自动准备环境时，二进制应用默认优先使用宿主机已有工具链，在独立目录从冻结源码快照构建完整可分发产物，再复制进 x11box 派生镜像运行；用户明确指定其他构建方式时遵循用户要求。Flutter Linux 传递完整 release bundle，包括引擎、资源和插件动态库。Agent 需要检查架构、glibc、ELF 解释器和动态库兼容性，特别是 NixOS 的 `/nix/store` 引用；无法本地构建或解决兼容性时，说明具体原因后回退容器内编译。原项目保持只读，应用只在容器内启动。

本地构建目录由 Agent 按项目约定自行选择，优先使用项目内、被快照排除的独立临时目录（例如 `.cache/` 下），避免写入 Bridge 元数据目录而触发额外审批。Agent 在 JSON 的 `artifact_directory` 回传完整可分发目录，Bridge 校验目录确实位于项目内且存在，保留权限和符号链接，作为 Docker 上下文的 `.omni-local-artifacts/` 提供。镜像将产物复制至 `/opt/omni-app/`，避免被运行时 `/workspace` 的源码覆盖。自动环境缓存包含完整源码摘要，源码改变会重新准备环境，防止复用旧二进制。

Docker daemon 与宿主机其他应用共享。环境准备 Agent 应只通过 `docker image inspect <本次基础镜像 sha256 ID>` 检查指定镜像，不能全局枚举镜像或容器。启用自动审批时，Bridge 根据内部会话与正在准备的环境记录核对镜像 ID，对匹配的只读检查直接放行；其他镜像、其他会话、复合命令及 Docker 修改操作继续使用原审批规则。

环境准备或桌面启动失败时，验收先显示失败阶段和原始错误，再清理容器与网络。自动清理完成后仍保留失败状态和诊断，不会改成已完成或清除原始错误。磁盘写满等状态保存错误保留在内存并写入 Bridge 日志，列表和详情不会因读取旧状态而持续显示“构建中”；磁盘空间不足会附带释放空间后重试的提示。后续成功保存会清除保存失败的临时状态。

验收列表和详情响应的 `pending_approvals` 汇总本次验收的环境、需求提炼和执行 Agent 的实时审批请求，不将审批快照持久化为事实来源。客户端在验收列表或详情页自动弹出审批框，展示原因、完整命令和自动审核原因；可批准、拒绝或按请求支持的选项取消、允许本会话。提交失败可重试，其他客户端处理后弹窗自动关闭。

## 确认测试用例

新的自动验收先生成供用户审阅的测试用例（标题、操作步骤和预期结果），进入 planning / awaiting_plan_approval。此时只冻结源码和需求，不构建项目镜像、不启动桌面，也不执行验收。用户可在详情页增删或编辑用例，或与 Agent 沟通调整；草稿和沟通记录持久保存。Agent 调整期间不能确认或编辑，服务失败会保留原稿供重试。

POST /v2/acceptance/{id}/test-plan 保存手动编辑的 cases；/test-plan/messages 接收调整意见；/test-plan/confirm 确认执行。以上请求携带当前 version，过期版本返回冲突；重复确认同一版本不会重复启动。确认后冻结用例版本，再准备环境、启动应用，并将已确认用例转成桌面/浏览器指令。执行清单必须覆盖确认后的用例，不恢复用户已经删除的原始要求。初次生成失败可 POST /test-plan/retry 重试。项目入口的手动远程桌面保持直接启动。

## 按项目准备运行环境

安装插件只准备公共 x11box 基础镜像。项目或会话的启动对话框可进入“项目运行环境”，选择：

- Agent 自动准备（默认）：只读分析项目清单、SDK 约束和启动方式，生成完整 Dockerfile；已有工具足够时直接使用基础镜像。
- 基础环境：不额外准备 SDK，适合基础镜像已经能运行的项目。
- 自定义 Dockerfile：填写完整 Dockerfile；使用 FROM {{BASE_IMAGE}} 继承已安装镜像。构建上下文为本次冻结的源码快照，支持多阶段构建。最终镜像必须保留 uid 1000 的 x11box 用户及可写工作目录、桌面和控制接口。
- 已有兼容镜像：从已准备列表选择，或输入本地/仓库镜像名（允许 tag）。首次准备解析为不可变 image ID，后续运行固定使用该 ID。要更新浮动 tag 的实际版本，选择“下次重新识别并准备环境”。

配置与状态存放在插件数据目录的 environments/ 下，不修改项目文件。接口为 GET/POST /v2/projects/{project_id}/acceptance-environment；POST 参数为 mode（auto/base/dockerfile/image）、dockerfile、image、rebuild。保存配置仅影响下一次运行，已运行桌面继续使用自己的镜像。

首次进入时异步识别、构建、检查 SDK，再验证 Xpra HTML5、控制接口及截图。运行详情显示环境阶段、生成的 Dockerfile、构建日志和错误。同一环境的并发请求只构建一次。准备失败不会启动错误的基础环境，可重试或修改配置；重启时未完成的准备被标记为中断。停止运行不会让准备完成后再启动该运行，但已经开始的环境准备可以继续完成缓存。

自动环境识别、下载地址预检、构建或 SDK 检查失败时，会将真实诊断、当前 Dockerfile、检查命令及此前失败方案交给 Agent，判断识别、版本、下载地址或检查命令是否有误。最近 10 条失败记录随环境配置持久化，提示词限制为最近 48,000 字符；新建 Agent 会话和手动重试仍能读取历史。手动重试失败的自动环境时，先重新识别修正，避免直接执行旧错误方案；成功的 Docker 构建层继续复用。

环境识别 Agent 可以只读查阅官方文档、读取发布清单并验证下载地址，也可以使用本机工具链在项目内独立目录中解压冻结快照、恢复依赖和构建完整应用产物；不得修改既有源码、配置、宿主机系统配置或在宿主机运行待验收应用。默认优先本地打包，再交给 x11box 运行。本地构建必须先读取实际应用子目录的 README 和开发环境声明；Nix 项目优先使用快照中的 nix develop/nix-shell，保留 SDK、JAVA_HOME、pkg-config 和 CMake 环境，不得从 /nix/store 随意搜索并直接调用 SDK 内部入口。Flutter 的 sky_engine 路径错误等必须先在项目声明的环境中诊断重试，不能仅凭一次脱离项目环境的失败就改为容器内编译。冻结的 flake.nix、flake.lock、shell.nix、.envrc、devenv 配置独立提供给 Agent，避免多项目依赖清单截断时丢失；引用的 Nix 模块也纳入依赖指纹和构建上下文。

启用 AI 自动审批时，Bridge 根据活动验收记录核对内部 Agent 身份、阶段、有效期及已确认用例，向审核器提供真实验收范围、指定容器和镜像。范围内无害的环境准备、Nix 构建、依赖下载、打包、容器内启动与重启、诊断、可逆测试数据准备、界面操作、截图录屏、报告和自身临时文件清理自动通过；支持命令、文件修改和权限请求。普通会话不继承验收授权，未确认用例仅允许规划分析；完整请求仍须经过风险与范围审核。

生成方案需要通过 download_urls 提供实际使用的发布清单、安装脚本和 SDK 归档的具体 HTTP(S) 地址（无变量，最多 16 个）。Bridge 在构建前独立检查这些地址，跟随最多 5 次重定向，每次请求限时 20 秒；HEAD 不受支持时使用 Range GET，仅读取响应头，不下载整个 SDK。失败诊断包含 URL 和 HTTP 状态，进入同一有上限的修正循环。预检在 Bridge 所在网络执行，使用配置的构建代理；成功仅表示地址可访问，实际容器构建、校验和及 SDK 检查仍需通过。

默认最多执行 3 轮（含首次执行，即最多自动修正 2 次），可通过 OMNI_CODE_X11BOX_ENV_MAX_ATTEMPTS 配置总轮数，范围 1–10；设为 1 可关闭自动修正，无效值使用默认值，超出范围的数字限制在边界。配置在 Bridge 启动时读取，达到上限后保留最终错误和构建日志。自定义 Dockerfile、指定镜像和基础环境不会由 Agent 自动修改。

应用启动进程提前退出时，会立即读取启动日志并让 Agent 修正一次启动方式；活着的编译进程可等待至多 15 分钟。启动命令继承镜像的 SDK PATH，避免使用登录 shell 覆盖路径。包含原生插件的 Flutter 项目可能还需缓存 CMake/FetchContent 拉取的第三方原生源码；仅缓存 Dart 包不等于所有原生依赖都可离线构建。

构建网络仅由服务管理员配置。可设置 OMNI_CODE_X11BOX_BUILD_PROXY=http://127.0.0.1:7890；指定代理时默认使用 host 构建网络，也可用 OMNI_CODE_X11BOX_BUILD_NETWORK=default/none/host 显式选择。代理通过 Docker 的预定义 build args 传递，不写入项目 Dockerfile 或运行镜像；这些选项不会修改验收容器的隔离网络和防火墙。Bridge 重启后重试即可保留和复用此前成功的 Docker 构建层。

自动环境按项目、不可变基础镜像、配置和完整冻结源码缓存（本地产物也随源码变化）；依赖清单、锁文件、SDK 版本文件或应用源码变化都会重新识别。自动构建仅提供依赖相关文件，启动时另行解压本次完整源码，避免在环境镜像中固化旧应用。自定义 Dockerfile 可以复制完整源码，因此完整源码变化会生成新环境。新环境保留其 Agent 识别的启动方式供后续复用，强制重新准备可清除旧识别结果。Docker 构建缓存仍可复用公共 SDK 层。

Flutter 环境由 Agent 根据 .fvmrc、pubspec.yaml、锁文件和目标平台准备 SDK、Linux 编译依赖及包缓存。支持接入已有的 Linux/Web 启动和验收流程；Android 模拟器和 iOS 验收仍未接入。本次真实镜像测试验证了派生构建、桌面接口和复用，并不代表任意 Flutter 项目均已通过端到端验收。

真实派生镜像验证：

    X11BOX_TEST_IMAGE='sha256:<完整摘要>' cargo test --no-default-features real_derived_image_is_verified_and_reused -- --ignored --nocapture

当前限制：最多 4 个活动验收；容器 2 CPU、4 GiB 内存、512 个进程；最长 4 小时；Bridge 每 30 秒清理过期运行。长期停机时，尚不能保证容器自行退出。

源码快照存放在验收运行目录的 `source.tar`。Git 提交快照和普通目录快照均排除各层级的 `build/`、`target/`、依赖缓存及 `.omni-code/`，避免将编译产物和运行状态重复归档。验收完成或取消后删除源码快照，报告、录屏和运行记录继续保留；仍被启动任务读取的快照延后至任务结束后的维护周期清理。等待计划审批和正在执行的验收保留快照。创建失败会清理半成品，维护任务还会清理超过 24 小时且没有 `run.json` 的遗留快照。

真实验证：

	X11BOX_TEST_IMAGE='sha256:<完整摘要>' cargo test real_container_acceptance_lifecycle -- --ignored --nocapture

移动浏览器测试还需 Node、Playwright 和 Chromium，并设置 NODE_PATH。测试必须验证连接、触摸、中文输入和控制撤销。Android/iOS 真机软键盘与网络切换仍需独立验收。

## Codex profile 会话聚合

Bridge 只使用一个自身数据目录。会话列表会扫描 Codex 的 `$CODEX_HOME/config.toml` 和同目录下的 `<profile>.config.toml`，并根据 Codex 会话 JSONL 中的 `model_provider` 识别来源。`/v2/sessions` 返回 `profile_id` / `profile_name`，`profile_id` 查询参数可以筛选；`/v2/codex/profiles` 返回发现的 Codex profile。
在项目页进入“应用验收”，创建或打开运行，再点击“打开远程桌面”，桌面会在 App 内的 WebView 显示。

WebView 会使用 Android 系统代理。若模拟器设置了 10.0.2.2:7890 等代理，代理进程可能无法访问模拟器专用的 10.0.2.2 地址，导致桌面请求返回 HTTP 502，而 Flutter 的 Bridge API 仍正常工作。先记录模拟器原有代理配置，再在本机调试时停用该代理：

    adb shell settings get global http_proxy
    adb shell settings put global http_proxy :0

返回 App 点击“重试”会取得新的单次票据；不要刷新已消费的票据 URL。故障排查应检查 WebView 的实际 HTTP 状态、页面画面和远程输入，桌面浏览器的移动视口测试不能代替 Android WebView 验证。

### 手机显示与操作

桌面默认按比例适应可视区域，保留验收时选择的分辨率；横竖屏切换只调整显示比例。顶部保留“适应屏幕”和“手机键盘”。单指轻点操作，单指拖动查看放大的桌面，双指滑动滚动远端内容，捏合缩放；双指轻点右键，快速连点双击，长按后拖动远端对象。

键盘默认收起。网页输入框，以及通过 AT-SPI 暴露可编辑焦点的 GTK、Tauri/WebKitGTK 原生输入框，点击后自动显示手机键盘。焦点检测只读取前台应用，并跨进程遍历 WebKit 的无障碍节点；查询超时、没有无障碍接口的应用保留“手机键盘”按钮。原生检测需要镜像包含 `at-spi2-core`、`python3-gi` 和 `gir1.2-atspi-2.0`；旧镜像需补齐这些包并更新准备环境使用的不可变 image ID。文字直接进入远端应用，支持中文输入法组合与候选词替换、emoji、退格，以及方向键、Ctrl/Alt/Shift 组合键和复制、剪切、粘贴。软键盘显示时保持桌面文字比例，并将最后点击的位置移入可视区域。

锁屏或切到后台后返回，客户端会重新取得桌面票据和控制权；顶部“重试”按钮也可重新连接。移动交互页面由 Bridge 提供，更新客户端时必须同时更新 Bridge，单独覆盖安装 APK 不会更新正在运行的旧版桌面页面。

Unicode 输入使用 Xpra 的 UTF-8 剪贴板通道，并按顺序执行后续编辑操作。剪贴板优先使用 UTF8_STRING；关闭 iframe 的剪贴板轮询，由外层输入框处理粘贴，避免旧剪贴板覆盖新复制的内容。Android 客户端将远端复制结果交给系统剪贴板。

文字过小时，双指捏合放大；点击“适应屏幕”回到完整画面。需要验收手机布局时，新建运行选择 mobile（390 × 844）；查看 PC 桌面时无需改变验收分辨率。

规划和执行使用独立 Agent 会话，旧版共享会话在执行时迁移。运行中失败且桌面仍有效的验收可 POST /v2/acceptance/{id}/retry，复用冻结用例和已有环境；可传 startup 指定已修复的启动方式。已结束或过期的验收需重新创建。

原生执行计划在运行前校验每条 action：仅接受可执行的 X11 指令，拒绝说明文字、占位符坐标和浏览器指令，交给 Agent 修正后再执行。每次自动验收重试使用新的消息幂等标识，避免复用之前失败的计划或判定。

失败重试支持仍在运行的桌面：执行故障，以及已生成不通过结论的 awaiting_confirmation 任务，均可通过 POST /v2/acceptance/{id}/retry 重跑已确认用例。重试不重新确认范围，但会重新读取画面并生成新的逐步证据。

原生输入依赖 x11box 激活窗口后使用 XTEST 向焦点发送键盘事件，避免 xdotool --window 的 XSendEvent 被 Flutter 忽略。已安装的不可变镜像需重建才能包含 x11box 源码修复。Flutter 使用 Nix SDK 打包时，运行库仅作用于应用进程，根据目标镜像验证并保留匹配的 EGL vendor、图形驱动及运行库；不要把 Nix LD_LIBRARY_PATH 注入整个桌面。若应用不支持启动时调整渲染尺寸，验收桌面使用与原生窗口一致的 geometry。

视觉步骤调用使用各自声明的 Agent 超时（通常 180 秒），不再强制增加到 600 秒；耗时诊断启动仍可显式使用 600 秒。每次点击、输入和快捷键后默认留出 7 秒给原生渲染完成（可配置），再采集下一步图片；是否成功仍由截图和断言判断。

服务在执行中重启时复用已确认范围和持久化清单，已完成的检查及截图不会重跑；尚未完成项基于当前画面继续。只有执行器保存的检查结果可以用于恢复，Agent 新生成计划中的 status/notes/evidence 会清空，防止用计划声明跳过真正操作。只剩判定阶段时不重开录像，避免覆盖已导出的证据。

## 环境观测与失效

自动准备先将宿主机观测、冻结项目配置和基础镜像观测分别交给 Agent，确认项目声明的开发环境后再选择构建方式。Nix、mise/asdf、Rust、FVM、Python、Node 与 devcontainer 版本文件保留子目录结构；未覆盖的工具仍由 Agent 根据项目说明检查，不按技术栈白名单决定可用性。

宿主每次准备/失败重试重新探测 OS、架构、libc、公开工具路径、符号链接目标和文件元数据，不执行 SDK 的自更新入口、不加载项目 shell 配置、不输出任意环境变量。自动方案遇到宿主指纹变化、旧观测缺失/失败或超过一小时会失效；重新识别也会清除旧启动方案。工具版本与原生依赖仍须在实际项目环境里验证，元数据指纹不是对所有系统状态的完整证明。

不可变基础镜像观测按摘要缓存一小时，失败重试强制刷新；临时探测容器只读、无网络、无宿主挂载并有资源/时间限制。观测失败记录为未知，不能据此断言工具不存在；强制刷新失败时删除旧缓存。应用启动修正后仍失败时，匹配该镜像的自动环境方案会失效，下次准备重新识别；不改写用户指定的 Dockerfile/镜像方案。实际运行容器在启动识别、启动失败诊断和每项视觉验收前重新观测，保存在该运行的 runtime-environment.json，不与宿主或镜像缓存混用。

输入后截图宽限时间默认 7000 ms，可通过 OMNI_CODE_ACCEPTANCE_SETTLE_MS 调整（250–30000 ms）；截图内容仍是判断 UI 是否发生预期变化的依据，宽限时间不是通过条件。

运行时仍要求 Linux Docker 与 x11box 桌面接口；本次通用化不表示已经支持 Windows/macOS 原生宿主或 Android/iOS 模拟器。用户安装的自定义镜像应满足同一接口契约，项目逻辑不依赖开发机器路径、固定镜像摘要或单一发行版软件清单。

## 执行证据与重新判定

执行器允许诊断并恢复中间工具、协议和启动错误。最终裁判必须检查后续真实操作和截图是否证明恢复，不能仅凭历史报错否定业务断言，也不能仅凭执行器的 passed 标签判通过。未解决错误、失败/阻塞/未完成执行、缺失截图仍不能通过；整体来源证据不足的失败结论不会被逐项结果覆盖。

POST /v2/acceptance/{id}/rejudge 仅复核尚未人工确认、处于 awaiting_confirmation 的运行，使用原始 visual-check-N.json 与留存截图，不执行 UI、不重开录像。记录的 id/assertion 必须匹配当前已确认清单，执行状态必须终结，所有引用截图必须存在。复核期间拒绝并行重试/复核，旧结论保留至新判定完整返回；判定期间运行状态发生变化则拒绝覆盖。请求、输入、旧结论和新结论以独立 JSON 留存，复核失败保留原结果并显示原因。服务恢复也读取原始执行记录，避免把裁判改写过的结论当作执行结果。

裁判输入包含冻结 revision、环境构建记录、运行镜像及留存源码归档摘要。目录快照重新计算 SHA-256 与 revision 比较；Git 提交标识不与归档摘要混比。归档缺失记录为未知，来源不一致或环境镜像与运行镜像不一致强制整体失败。构建目录和日志属于构建记录，不声称提供独立的源码到二进制密码学证明。逐步模型等待耗时写入 visual-check-N.json 的 decision_timings，便于区分模型调用与 UI 等待。

## 验收审批服务故障恢复

已绑定到活动运行、且范围已确认的验收会话，对常规构建和只读诊断先做本地范围检查。审批请求保留实际 cwd；检查工作目录、全部 shell 子命令、项目内日志重定向、符号链接目标和路径，支持系统 shell/timeout/Nix 包装及多种项目工具链。未知语法、任意脚本、范围外操作与敏感文件读取继续完整审核；不能仅凭命令名、理由或 acceptance 前缀放行。离线核实通过会记录 approval:auto 活动，不依赖远程审核服务或全局 AI 审批开关。

复杂操作的远程审核故障自动重试一次。持续不可用时，将明确错误交给验收任务的恢复流程，操作不执行，不把基础设施超时改成人工审批无限等待。普通会话保留原有审核行为。确需人工处理的请求会在验收 API 的 automation_progress 中显示“等待验收操作审批”；该展示从当前会话状态投影，不覆盖持久化执行进度。构建准备提示要求首次构建和重试均保存完整 stdout/stderr 和退出码，失败时读取实际错误，避免只留下 Build process failed。

Bridge 重启时，Starting 阶段的任务若尚未完成、未过期、保留源码归档且自动任务的用例版本已经确认，则保留 Starting 并恢复环境准备，不再被维护线程当作失败运行清理。停止中、过期、缺少归档或缺少确认的任务不自动恢复。恢复准备使用原归档和已确认用例；同一进程内按运行 ID 去重。半途遗留的同名容器/网络仅在带有 Bridge 所有权标签时重建，其他资源不覆盖。

环境观测记录常见安装目录本身及链接属性，模型生成打包方案时需核对目标目录，不能假定基础镜像中的绝对依赖路径不存在。Docker 每个操作记录独立输出起点；失败或超时只返回当前操作的日志及退出状态，静默失败明确说明没有输出，避免将此前成功构建日志误当成运行验证错误。验证脚本需输出具体失败检查点和缺失路径。


## 容器验收回归脚本

运行 scripts/test-acceptance-docker.sh，验证镜像探测、派生镜像复用、原生桌面、Web 生命周期和 Flutter 桌面构建点击录像。需要本地 Docker、Cargo 和测试工具链。默认镜像为 omni-x11box:acceptance 和 omni-x11box:flutter-acceptance，脚本会解析为不可变镜像 ID；可用 X11BOX_TEST_IMAGE 和 FLUTTER_TEST_IMAGE 指定兼容镜像。标签缺失时先检查已有镜像再补标签。脚本不会下载镜像，缺失会明确失败。移动网关和 Android/iOS 真机需另外验证。


## 子目录项目与开发环境识别

验收配置的程序识别会扫描项目根目录及最多 4 层子目录（最多 128 个目录、4096 个目录条目），跳过隐藏目录、依赖目录和常见构建产物目录，不跟随符号链接，也不执行项目脚本。发现唯一项目时，生成相对根目录执行的命令，例如 cd 'apps/client' && flutter build linux --release。发现多个项目或扫描不完整时，API 的 candidates 保留各目录独立的配置、依据和环境提示。环境审阅页接收本次显式验收需求及来源会话；有需求上下文时会自动让 Agent 判断相关项目，允许同时选择客户端、后端服务及必要依赖，并解释各自作用和选择理由。没有当前需求时可在页面补充，也可手动多选。

POST /v2/projects/{id}/acceptance-environment/detect 支持 requirements、session_id 和 current_targets；来源会话必须属于当前项目。会话复用验收的时间顺序分批机制，保留早期需求和后续纠正，显式验收重点优先；Agent 回复仅作辅助上下文。每批使用独立分析会话，携带此前的有界整理结果，避免历史消息不断累积。识别仅分析已提供文本，不执行工具或项目命令。返回 targets 列表及 reasoning，每个项目含 directory、role、reason 和独立 configuration；目录必须来自识别候选，不接受目录越界或重复目标。未确定字段保留为空。

用户可切换各相关项目编辑其配置，切换不会丢失其他项目的修改。首次自动识别填入待审阅表单，主动再次识别仍需点击应用。保存将完整列表写入 build_targets，并保存 build_reasoning；旧版单项目 build 配置继续兼容。环境页修改的验收需求也传入后续实际验收。运行环境的标识包含全部相关项目配置，后端配置变化不会复用旧环境。执行器收到完整列表，分别构建各项目，协调依赖、服务就绪、容器内启动和退出清理，不把多个阻塞式启动命令简单串联，也不借用宿主机已有服务冒充本次冻结源码的产物。

相关目标指需要独立准备的产品组件。由主项目包管理器自动构建的内部库不重复列入；浏览器测试或 Playwright 等验收工具也不会仅因需求涉及界面交互或端到端验证就成为独立运行目标，除非用户明确验收测试工程本身或产品运行确实依赖它。

Nix 环境优先使用应用目录自己的 flake.nix 或 shell.nix；没有时向上查找项目根目录以内最近的 Nix 声明，生成相对应用目录的环境入口。命名 devShell 和实际可用性仍需确认。其他开发环境声明会带目录路径显示在识别依据中，Agent 再识别也会收到子目录清单及环境文件；上下文单文件上限 64 KiB、总文本上限 512 KiB，省略内容时附带提示。
